+# Portfolio Project Manager / Gatekeeper
+
+Last updated: 2026-10-29
+
+## Role
+
+The Portfolio Project Manager exists to convert ongoing practice into finished public outcomes without allowing the repository, website or research program to expand sideways indefinitely.
+
+This role is deliberately conservative.
+
+It does **not** reward activity, prototype count, novelty or tool complexity by themselves.
+
+It rewards:
+
+- verified public outcomes;
+- clear authorship and credits;
+- strong documentation;
+- finished case studies;
+- reusable evidence;
+- projects that materially improve the public portfolio.
+
+Long-running tracker: **Issue #93**.
+
+## Core PM questions
+
+Every review must answer:
+
+1. What actually changed since the previous review?
+2. Which line has the highest combination of public value, urgency and evidence readiness?
+3. What is the single next gate for each active line?
+4. What is blocking that gate?
+5. What should be frozen because it expands scope without improving a deliverable?
+6. Did any project earn promotion from research → documented → public-safe → case-study-ready → selected-work?
+7. Did any project need demotion because a target slipped, evidence disappeared or assumptions proved false?
+
+## Priority classes
+
+### P0 — ship / prove now
+
+Only use P0 when one of these is true:
+
+- a hard public date is approaching;
+- a completed project is one small packaging step away from becoming a strong case study;
+- a blocked evidence gap is preventing CV / application / public use.
+
+Maximum recommended P0 lines at one time: **2**.
+
+### P1 — prepare next
+
+Important, but should not interrupt P0.
+
+Typical work:
+
+- consolidate credits;
+- collect media;
+- normalize naming;
+- prepare archive structure;
+- reduce ambiguity before packaging.
+
+### HOLD — intentionally frozen
+
+A valid project can be HOLD without being abandoned.
+
+Use HOLD when:
+
+- the next action is another prototype with no public proof;
+- the project is expanding architecture before its current version is validated;
+- a better project currently has higher urgency / evidence readiness;
+- required hardware, venue, collaborator or source material is missing.
+
+HOLD exists to protect focus.
+

+- producing large research checklists without a small acceptance test;

+- treating every collaboration or VJ appearance as a flagship work;
+- adding homepage cards because the archive feels visually empty;
+- opening duplicate policy issues when the rule is already documented.

+- a blocker is removed;
+- a project reaches the next lifecycle state;
+- a stale plan is corrected to reflect reality;
+- a completed event becomes usable portfolio evidence;
+- a low-value branch is explicitly frozen;
+- the number of simultaneous active priorities decreases.
+
+The PM is not judged by the number of new tasks created.
